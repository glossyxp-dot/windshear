# Controls

The defaults, and why they are what they are.

---

## The rule

**The mouse is the camera, and the mouse is optional.**

A player holding the mouse is not holding a movement key. So every action in
the game has at least one keyboard binding, and the mouse bindings are extra
routes to the same action rather than the only route. If you never touch the
mouse, you can still run, slide, jump, wall-kiss, mantle, throw the
Filament, turn the camera, shoot, reload, use an item and switch weapons.

The input map is generated by `tools/setup_input_map.gd` rather than
hand-written, because a hand-written `[input]` section in `project.godot` is
a wall of `Object(InputEventKey, ...)` lines that nobody reviews.

`tests/test_input_map.gd` holds the rule. If an action ever loses its
keyboard binding, or if something ends up mouse-only, the build fails.

## Keyboard

### Left hand — moving

| Action | Keys |
| --- | --- |
| Move left / right | `A` `D`, or `←` `→` |
| Jump | `Space` |
| Slide | `S`, `↓`, or `Ctrl` |
| Mantle / ledge grab | `W`, or `↑` |

### Right hand — acting

| Action | Keys |
| --- | --- |
| Turn the camera | `Q` `E` |
| Tilt the camera | `Page Up` `Page Down` |
| Filament (tether) | `F` |
| Fire | `Z` |
| Aim | `X` |
| Reload | `C` |
| Use item | `B` |
| Next weapon | `V` |

### Anywhere

| Action | Keys |
| --- | --- |
| Reset to checkpoint | `R` |
| Splits | `Tab` |
| Mechanics reference | `F1`, or `H` |

The camera turns at a fixed rate on the keys and by pixels on the mouse, and
the two rates are different on purpose. A key turns at 2.0 rad/s, which is
slow enough to line the camera up. The mouse is 0.0022 rad per pixel, which
is fast enough to whip past a target and come back.

## Mouse

| Action | Mouse |
| --- | --- |
| Look | Move the mouse |
| Fire | Left button |
| Aim | Right button |
| Next weapon | Wheel |

The right mouse button is **aim**, not the Filament. The Filament is a
movement verb and it lives on `F`, where it can be pressed while the mouse
is still moving the camera.

## Controller

| Action | Pad |
| --- | --- |
| Move | D-pad, left and right |
| Jump | A |
| Slide | B |
| Mantle | X |
| Filament | Right shoulder |
| Fire | Right trigger |
| Aim | Left trigger |
| Reload | Y |
| Use item | D-pad up |
| Next weapon | Right stick click |
| Turn and tilt | Right stick |
| Reset / splits / help | Back, Start, Guide |

The left stick is free for movement and the right stick does the camera, so
the two never fight over the same axis.

---

## Remapping

The bindings are in `project.godot` under `[input]`, and they are meant to be
edited — by hand or through the Godot input map editor. If you change one,
change it in `tools/setup_input_map.gd` as well, or the next person who runs
the generator will quietly undo your work.

The keys the suite insists on are the ones the game needs to be playable
without a mouse. Anything else is yours to move.

## The greybox

Open `world/greybox/movement_greybox.tscn` and press `F1`. The panel lists
the movement numbers read straight from the tuning constants, and the new
camera and tether bindings underneath them.
